pub fn sanitize_filename(filename: &str) -> String
Expand description

Replaces disallowed characters in filename with underscores and truncates it to at most MAX_FILENAME_LEN bytes, on a character boundary.

Only letters and digits of any script, printable ASCII characters, and spaces are allowed, except for reserved characters, i.e., . and / (and, on Windows, the other characters that Windows doesn’t allow in filenames). Names come from the analyzed binary, so this keeps out control characters, which are invalid in Windows filenames and could inject terminal escape sequences when paths are printed, and Unicode format characters, such as bidirectional isolates and zero-width spaces, which could reorder or hide parts of a printed path (IDA 9.5 keeps some of them in names). Allowing known-safe characters, rather than denying known-dangerous ones, also covers characters that future Unicode versions may add. Other non-ASCII symbols, such as emoji, are replaced too.

Letters of any script are kept, so a sanitized name can still look like another one (e.g., with look-alike letters from another script, invisible Hangul fillers, or stacked combining marks), and different names can give the same result (e.g., a.b and a/b): output_path_for_function appends the function’s address, which keeps its file names distinct.

Counting bytes rather than characters keeps output filenames within the usual 255-byte limit on filename length, even for names made of multi-byte characters and once output_path_for_function appends its @ADDR.c suffix.
